## Files

| File | What it is | When to edit |
|---|---|---|
| `config.yaml` | All settings: data, model, training, logging | Most changes go here |
| `data.py` | The dataset and data loaders (`build_datamodule()`) | To use other data, transforms or splits |
| `model.py` | The network, loss and optimizer (`build_model()`) | To change the model |
| `train.py` | Runs the training; the same for every task | Rarely |
| `lightning-job.slurm` | The Slurm job: resources, modules, `srun python3 train.py` | To change time, memory or GPUs |
| `env.sh` | The modules this run uses | To change software versions |
| `.drona/` | Drona's support code and monitor scripts | No need |

## Common changes

| To change | Edit in `config.yaml` | Value at generation |
|---|---|---|
| Number of epochs | `training.max_epochs` | {max_epochs} |
| Batch size | `data.batch_size` | {batch_size} |
| Learning rate | `training.learning_rate` | {learning_rate} |
| Precision | `training.precision` | {precision} |
| Where logs go | `logging.log_dir` | `{log_dir}` |

For one run without editing the file, add `--set`, for example:
`python3 train.py --config config.yaml --set training.max_epochs=20`

To run again with the same resources: `sbatch lightning-job.slurm` in this directory.

## Run interactively

On a compute node (for example in an interactive job), from this directory:

```bash
source env.sh
python3 train.py --config config.yaml --set training.max_epochs=1
```

On a node without a GPU, add `--set training.accelerator=cpu`.
